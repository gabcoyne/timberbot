    Mock Fidelity & Timberborn 1.1 Source Matrix¶

    This document records the exact provenance of every HTTP/WebSocket API shape, failure mode, and Timberborn 1.1 game mechanic modeled in rust/crates/timberbot-mock, rust/crates/timberbot-protocol, rust/crates/timberbot-save, and skills/.

    No number is marked verified without a cited primary source. Everything else is explicitly labeled approximated (intentional simplification for deterministic offline CI) or guess / unverified (requires a live Timberborn 1.1 install and playtest).

    Status Legend¶

    Status Meaning
    verified Confirmed directly from this repository's C# mod source (timberbot/src/*.cs), recorded golden OpenAPI fixtures (python/tests/fixtures/openapi/*.json), openapi.yaml, official Timberborn Wiki (timberborn.wiki.gg), Mechanistry Update 1.1 patch notes, or 0xguy07/timberborn-tools (verified on 1.1.2.4).
    approximated Real-game value or rule is known, but timberbot-mock intentionally uses a simplified deterministic model (e.g., 1D river depth instead of 3D Unity fluid solver, simplified path reachability) so offline tests run fast and repeatably.
    guess Not yet proven from primary public docs or a live Timberborn 1.1 binary; treated as unverified and flagged for real-game confirmation.

    3. Intentional Approximations in timberbot-mock¶

    To keep cargo test --workspace deterministic and fast (~1 s without Unity or game DLLs), timberbot-mock deliberately approximates:

    1. 2D water, floodgate bypass & irrigation grid (approximated): Models a 2D 32×32 tile grid (water_grid, contam_grid, moist_grid) across the 3-wide river channel (x = 9..=11) with downstream wave propagation (WATER_PROPAGATION_TILES_PER_DAY = 24.0 tiles/day, approximated), per-tile floodgate blocking (center-channel x = 10 sluices span the channel; off-center gates at x = 9 or x = 11 allow 2D lateral bypass), verified wiki evaporation rates (0.0534 m/day wide pool, 0.096 medium, 0.200 narrow), and 2D multi-source BFS irrigation up to verified IRRIGATION_MAX_RADIUS = 16 from clean wet river tiles (contam < 0.50). Full 3D voxel fluid pressure, waterfalls, and -6-tile elevation irrigation falloff remain unverified / not modeled.
    2. Builder queues & construction work-hours (approximated): Only Path and Flag prefabs finish instantly (0.0 h). All real buildings require hauling (HAUL_ITEMS_PER_BUILDER_HOUR = 12.0 items/builder-hr, approximated) followed by building work-hours (build_work_hours = 4..24 h, approximated), processed strictly by active builders (DistrictCenter + finished BuildersHut workers) in construction_priority order (VeryHigh -> VeryLow, FIFO tie-break). Zero builders means zero construction progress.
    3. 2D path connectivity, distance efficiency & hauling bottleneck (approximated):
    4. Reachability (approximated): 2D BFS from every finished DistrictCenter (core starter radius Manhattan <= 10) expanding along Path* tiles and adjacent buildings (step <= 2..3). Sites outside the core with no Path chain are marked reachable = 0 and cannot be constructed or staffed until linked. Exact BlockObjectSpec entrance tiles, stairs, and 3D terrain cliffs are unverified / not modeled.
    5. Distance efficiency (approximated): Workplaces and construction sites within Manhattan distance 6 of the District Center run at 1.0x; beyond 6 tiles efficiency scales by 1 / (1 + 0.025 * (dist - 6)).
    6. Hauling bottleneck (approximated): When zero builders/idle adults exist to haul across >= 4 active workplaces, workplace throughput scales by HAULING_BOTTLENECK_MULT = 0.75 instead of per-beaver Hauling Post task queues.
    7. 2D connected-component power networks (approximated): Power generators, PowerShaft tiles, and powered workshops form 2D connected components (POWER_CONNECT_CHEBYSHEV_DIST = 3) emitting separate PowerNetwork IDs in /api/power. Supply and demand are balanced strictly per network component; disconnected workshops remain unpowered (powered = 0) even when another network has surplus hp. Directional shaft ports (Straight/Turn/T/Cross, vertical shafts) and gear-box routing are unverified / approximated as isotropic links.
    8. Reproduction cadence: Folktails kits spawn when free beds > 0, ≥2 adults exist, and no hunger/thirst crisis; Iron Teeth kits spawn from staffed/supplied BreedingPod cycles (5 Water + 5 Berries / 5 days verified, exact pod scheduling approximated).
    9. Wellbeing bonuses: Approximates colony work-speed multiplier from average wellbeing using the verified wiki curve anchors (WB 0 -> 1.0x, WB 5 -> 1.2x, WB 15 -> 1.6x, WB 70 -> 3.6x).
